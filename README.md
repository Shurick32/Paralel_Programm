# Параллельное программирование (Блочная оптимизация и работа с кэш-памятью)

## Цель работы

Исследовать зависимость времени выполнения программы от размера обрабатываемых данных и размера блока (tile) при использовании блочной декомпозиции.

## Задание

Реализовать программу вычислений над матрицами с использованием блочного подхода. Провести эксперименты при различных размерах входных данных и различных размерах блоков (`Block_X × Block_Y`).

## Описание программы

Программа выполняет вычисления над квадратными матрицами, используя блочную декомпозицию для улучшения локальности данных и эффективного использования кэш-памяти процессора:

- Входные данные разбиваются на блоки размера `Block_X × Block_Y`
- Каждый блок обрабатывается последовательно, что позволяет эффективно использовать иерархию памяти (кэши L1/L2)
- Уменьшается количество промахов кэша за счёт повторного использования данных, уже загруженных в быструю память
- Размер блока задаётся параметром и является ключевым фактором оптимизации производительности.

## Анализ результатов

### 1. Зависимость от размера задачи

С увеличением размера матрицы (`Size`) время выполнения закономерно возрастает. Это соответствует ожидаемому поведению алгоритмов с вычислительной сложностью $O(n^2)$ или $O(n^3)$, в зависимости от реализуемой операции.

### 2. Влияние размера блока на производительность

- **Малые размеры (200–500):** Наименьшее время достигается при блоке **8×8**. При малых объёмах данных накладные расходы на управление крупными блоками и возможные промахи кэша из-за неэффективного использования памяти перевешивают преимущества блочной оптимизации.
- **Средние размеры (1000):** Оптимальным оказывается блок **16×16**. Он обеспечивает баланс между локальностью данных и накладными расходами на итерацию по блокам.
- **Большие размеры (1500–2000):** Наилучшие результаты показывает блок **32×32**. При больших объёмах вычислений критически важным становится эффективное использование кэш-памяти: крупные блоки позволяют дольше удерживать данные в кэше L1/L2, снижая количество обращений к оперативной памяти.

### 3. Наблюдаемые эффекты

- **Закон убывающей отдачи:** После достижения оптимального размера блока дальнейшее его увеличение не даёт прироста производительности, а иногда и ухудшает результаты.

## Вывод

В ходе лабораторной работы была исследована эффективность блочной декомпозиции для оптимизации вычислений.

**Ключевые выводы:**

1. Размер блока является критическим параметром производительности и должен подбираться экспериментально для конкретной задачи и аппаратной платформы.
2. Для малых задач предпочтительны мелкие блоки (8×8), для средних — 16×16, а для больших объёмов данных оптимальными оказались блоки 32×32.
3. Блочная оптимизация позволяет существенно ускорить выполнение программы за счёт улучшения работы с иерархией памяти, однако её эффективность строго зависит от соотношения размера задачи, размера блока и характеристик кэш-памяти процессора.
